PrimitiveResolver Class

Indexes attached *.symbol.room files (PDK, commonLib, design-library cells) so Qucs and Xschem exporters can resolve Lib / devices/*.sym references. More…

Environment variables

LibMan and integrated editors set these when opening a schematic view with attached tech libraries:

VariableFormatDescription
CORE_PRIMITIVE_LIBS_FILE Path to a text file Preferred for large libraries (100+ symbols). One absolute path per line. Avoids oversized environment strings on Windows/WSL.
CORE_PRIMITIVE_LIBS ; or : separated paths Fallback when no list file is set.
CORE_PRIMITIVE_LIB Single path Legacy single-symbol attachment.
LIBMAN_TECH_LIBRARY ; separated names Logical library prefixes for symbol keys (e.g. commonLib, sg13g2_pr).
QUCS_PRIMITIVE_LIB Library name Qucs <Lib> name written by QucsExporter for PDK primitives.

primitiveCorePathsFromEnvironment() checks CORE_PRIMITIVE_LIBS_FILE first, then CORE_PRIMITIVE_LIBS, then CORE_PRIMITIVE_LIB.

Detailed Description

Each registered <cell>.symbol.room is indexed under multiple keys: bare cell.sym, <lib>/cell.sym, and (for commonLib) devices/cell.sym for Xschem compatibility. Alias tables map Qucs component types to Xschem device names (e.g. res ↔ R, gnd ↔ GND).

QucsExporter uses the resolver to emit native Qucs components where possible (res → R, iopin → Port) and <Lib> only for PDK/hierarchy cells without a built-in mapping. Xschem-only decorations (lab_wire, code_shown, launcher) are skipped in Qucs via isQucsSchematicDecoration().

Example

room::PrimitiveResolver resolver;
resolver.loadFromEnvironment();
// or manually:
resolver.setTechLibrary("commonLib;sg13g2_pr");
resolver.addCorePath("/data/commonLib/lab_pin/lab_pin.symbol.room");

const room::ResolvedPrimitive hit = resolver.resolveReference("devices/lab_pin.sym");
if (hit.found) {
    // use hit.roomPath in export/materialize
}
