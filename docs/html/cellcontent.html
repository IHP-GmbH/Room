Detailed Description

One view of a Cell (layout, schematic, symbol, or abstract).

On disk (.core v1.0), view geometry is stored in payload — a ViewPayload union (schema/views.capnp). The active arm matches viewType (layout, schematic, …) and contains per-view layers[] plus a nested block (shapes, instances, nets).

In C++, use block() as the ergonomic accessor for that nested topology. SourceInfo records provenance from importers (Xschem, Qucs, GDS). Database::saveToFile() / loadFromFile() map between block() and payload.*.block. Tools that do not understand a view type can copy the opaque arm without decoding geometry.

Layer indices in shapes and terms refer to Lib::layers() at import time; the per-view layers[] inside payload is the serialized copy for that view.

Integer coordinates in block() are always stored in DBU. Layout views use dbuPerMicron for physical microns; schematic and symbol views use dbuPerEditorUnit to map to Qucs/Xschem file coordinates. See Coordinate scale.

double dbuPerEditorUnit() const

Returns DBU per one native editor coordinate unit for schematic and symbol views. Qucs uses 1; Xschem uses 1000 for sub-grid precision. Value 0 means unset — readers infer from SourceInfo.

See also: Coordinate scale, utils/coord_scale.h.

Example

core::Lib & lib = db.lib();
lib.layers().push_back({2, 0, "L2/D0", core::LayerPurpose::Drawing});
lib.layers().push_back({3, 0, "L3/D0", core::LayerPurpose::Label});

core::CellContent content(core::ViewType::Layout, 1000.0);
core::Block & block = content.block();
block.shapes().emplace_back(core::Shape::TextData{
    {100, 100}, "TOPCELL", 1, 200});
block.recomputeBBox();
